# tenomi-motion

[日本語](README.md) | **English**

The main body of TENOMI (an AI robot that needs no words) — a μT-Kernel 3.0 firmware running on the STM32N6570-DK that recognizes hand movement (motion) from camera video and judges its intent (gesture).

## What TENOMI is

TENOMI consists of three parts.

- **DK board (main body, this repository)** — STM32N6570-DK. Runs palm detection → hand landmark detection → motion inference on hand movement, **completing the whole pipeline on the board alone**. No post-processing on an external PC is required.
- **Bridge** — Raspberry Pi 5. Receives the DK board's judgment and relays it to other devices.
- **Rover** — A driving robot based on micro:bit v2. Moves according to the recognized gesture.

Bridge and Rover are handled in separate repositories, so this README covers only an overview of them.

## Layout

```
tenomi-motion/
├── landmarks/            Camera / NPU inference pipeline (palm detection, hand landmark
│                          detection, GPU rotation via NemaGFX, motion inference)
├── mtk3bsp2_stm32n657/    μT-Kernel 3.0 project (STM32CubeIDE, two configurations: Appli and FSBL)
├── tools/                 Setup and flashing scripts
└── dist/                  Build/flash output (created when you build)
```

## Requirements

- [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html)
- [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html) (bundles the External Loader; used for flashing)
- Git (used to fetch the NemaGFX library)
- Python 3 (used to merge HEX files)

## From clone to build

### 1. Clone

```sh
git clone https://github.com/tenomi-akkabane/tenomi-motion.git
```

### 2. Fetch the NemaGFX library binaries (`.a`)

NemaGFX (a GPU rendering library from Think Silicon) ships its headers and templates in this repository, but the compiled library binaries (`.a`/`.lib`) alone are not included. ST's license terms limit distribution to "binary form incorporated into a finished firmware."

```sh
# Windows
.\tools\setup_nema_lib.ps1

# macOS / Linux
./tools/setup_nema_lib.sh
```

This fetches them directly from STMicroelectronics' official repository (`x-cube-n6-ai-hand-landmarks`, tag `v2.2.0`) and places them under `landmarks/Lib/NemaGFX/lib/`.

You can still build even if you cannot fetch them. Setting `TENOMI_NEMA_ENABLE := 1` to `0` in `mtk3bsp2_stm32n657/Appli/Release/Application/hand_landmark/tenomi_build_opts.mk` (and the Debug counterpart) builds a CPU-only path that skips GPU rotation (detection accuracy drops somewhat).

### 3. Open the projects in STM32CubeIDE

Import the two projects `mtk3bsp2_stm32n657/FSBL` and `mtk3bsp2_stm32n657/Appli` into STM32CubeIDE (File > Open Projects from File System...).

### 4. Build

1. Build `mtk3bsp2_stm32n657_FSBL` in the **Release** configuration
2. Build `mtk3bsp2_stm32n657_Appli` in the **Release** configuration

## Flashing and running on the board

### 1. Flash

Put the DK board into **Development mode** (SW1=H, SW2=L), connect it to the PC, and run:

```sh
# Windows
.\tools\install_release.ps1

# macOS / Linux
./tools/install_release.sh
```

This signs the Appli binary, merges the FSBL, Appli, palm detector, hand landmark, and motion inference model HEX files into one, and writes them to the NOR flash via STM32CubeProgrammer — all in a single command (the output goes to `dist/tenomi_utk_release.hex`, among others).

### 2. Boot

After flashing, switch to **Flash mode** (SW1=L, SW2=L) and power-cycle the board. Palm detection, hand landmark detection, and motion inference all run standalone on the board from the camera feed, and the result is shown on the LCD/LED.

## What is not included in this repository

| Not included | Reason | How to obtain |
|---|---|---|
| NemaGFX library binaries (`.a`/`.lib`) | ST's license terms (distribution allowed only in binary form) | Fetched automatically by `tools/setup_nema_lib.ps1`/`.sh` (see above) |
| Build output (`dist/`, intermediate files under `Appli/Debug`/`Release`) | Build artifacts, not needed in the repository | Generated by following the build/flash steps |
